# Deviations and verification limits

This file records differences from DOC 00–07 and limits of the available evidence. It does not declare that every acceptance criterion passes. Paths below refer to the implementation in this repository.

## Compatibility adaptations

- **Three.js r187 material API:** `iridescenceThicknessRange: [200, 800]` is implemented with `iridescenceThicknessMinimum: 200` and `iridescenceThicknessMaximum: 800`. The installed version warns that the array property is deprecated. The intended thickness interval is preserved.
- **Three.js r187 shadows:** `PCFShadowMap` replaces the specification's `PCFSoftShadowMap` after the installed renderer's API warning. Shadow bias, normal bias, frustum, and configured tier map sizes remain explicit. The filtering implementation is therefore not the exact named algorithm in the original pack.
- **TypeScript version:** `6.0.3` is pinned instead of the available stable `7.0.2`. Installation with 7.0.2 failed because `typescript-eslint@8.72.1` requires TypeScript below 6.1. No forced peer dependency installation is used. See `ASSUMPTIONS.md` and `qa/dependencies.json`.
- **Shader compilation:** `compileAsync` is used when `KHR_parallel_shader_compile` is present. SwiftShader lacks that extension, so boot uses synchronous `compile` followed by warm rendering. This avoids the renderer warning but cannot guarantee an uninterrupted loader animation during compilation.
- **Missing half-float render support:** both the composer and nebula target use unsigned-byte buffers when the required color-buffer extension is unavailable. This is the resilience fallback required by DOC 07; HDR range and subtle gradients are reduced on that path. The fallback branch is present in code, but the current machines support half-float and do not establish its appearance on every unsupported device.

## Timing, performance, and validation limits

- **Boot work is not uniformly limited to 8 ms.** The queue and noise loops yield, and rock generation runs in a worker, but Three.js geometry constructors, PMREM generation, shader compilation, and GPU uploads remain indivisible calls in this implementation. The baseline long-task observer recorded boot tasks lasting hundreds of milliseconds and some over one second under software rendering. The strict all-work-within-8-ms requirement is not fully met.
- **Post-loader long tasks are not universally eliminated.** The first desktop observation recorded none, but its emulated-mobile software run recorded tasks over 50 ms. These are preserved in `qa/report-iteration1.json`. A clean build or a frame-count budget alone does not prove the long-task target on all devices.
- **Camera position continuity is not a proof of smooth acceleration everywhere.** The centripetal curves use the prescribed piecewise-linear arc-length timing remap. Position is continuous, but speed derivatives can change at timing knots. The damping reduces visible abruptness; it does not turn that remap into a continuously differentiable timing function.
- **Geometry/texture stability is a bounded test.** Five complete scroll loops are measured. This does not establish indefinite stability, every manual tier-change sequence, or a dedicated five-minute soak on a real phone. Instance resources are explicitly disposed; renderer resource counters do not measure all JavaScript heap allocations.
- **No discrete GPU or real phone has been tested.** The initial full suite uses Chromium ANGLE SwiftShader. Its FPS values are software-rendering observations and are not evidence of the requested 60 FPS discrete-GPU or 30 FPS phone targets. Supplemental runs use the machine's Intel UHD Graphics 730 when the renderer confirms that device; integrated-GPU results must retain that label.
- **Verification history is retained.** The first complete software suite produced 22 captures, 41 passing checks, one failed pointer/cursor check, and zero console issues, page errors, or external requests. The pointer check passed an isolated reproduction; that does not erase the baseline failure. Two subsequent software runs were interrupted and are saved as `qa/report-iteration2-interrupted.json` and `qa/report-iteration3-interrupted.json`; they are not complete passing runs. The completed Intel UHD 730 suite in `qa/report.json` has 22 samples and 42 passing automated checks, with zero browser warnings/errors and zero external requests. Medium/high budgets also pass in `qa/supplemental-report.json`. These automated passes do not cover every visual acceptance requirement.
- **Visual evidence is sampled.** Milestone and chapter screenshots support review at the tested positions. Slow-scrub and contrast checks, when completed, also remain sampled evidence. They do not prove every possible scroll position, lighting time, pointer state, display, or browser. Any acceptance item without sufficient evidence must remain NOT-RUN or FAIL in the final report.

Known source defects discovered during review—disabled-last-pass output on high/ultra, double tap shockwaves, camera rotation overwritten by look-at, inconsistent context-loss overlay styling, insufficient clearance accounting, and abrupt instance-count color transitions—were addressed in source. Their fixes are not substitutes for the final executed regression results.

- **AC-051 contrast remains below the requested bound.** `qa/contrast-report.json` hides foreground text while preserving scrims and evaluates the brightest pixels over whole text rectangles. Multiple conservative worst-region ratios are below 4.5:1. Broader 55% scrims, fully opaque body text, repositioned camera and dimmer nebula improved legibility, but the strict guarantee is not achieved. Rectangle measurements also include spaces and decorative rules; they must not be presented as a precise glyph-only conformance score.
- **Measured hardware performance:** the integrated Intel UHD 730 high tier measured approximately 9–33 FPS across six settled chapter samples at 1440×900. The requested discrete-GPU60FPS and physical-phone30FPS targets remain unverified.
- **Clean-install verification:** the first npm ci attempt encountered Windows EPERM because running Vite processes held its native binding. After stopping those task-owned servers, npm ci installed131packages successfully; typecheck, lint, geometry checks, singleThree verification and production build passed again.

- **AC-012 visual fidelity remains incomplete.** Final frames show night-side gold points and cloud darkening, but the orange/magenta sunset band remains weak, and independent cloud rotation is not matched by an exact projected shadow lookup. Reframing, localized lightning, a brighter lit limb, warm scattering and ring shadow were attempted. The complete requested terminator appearance remains unmet.
